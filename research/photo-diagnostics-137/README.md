# Фотографии: декодирование и кеш на исходниках 0.3.137

22 октября 2026 года. Диагностика завершена: по три прохода на эмуляторах
Android 8 / API 26 и Android 16 / API 36. Получено **210 наблюдений и 210
успешных запросов изображений**. Все **102 возврата** использовали память
Coil без нового чтения файла и декодирования. Ошибок изображений не обнаружено.

На этом маршруте оснований увеличивать кеш или исправлять повторное
декодирование нет. Первый запрос к файлу дороже повторного открытия. Его
замедление в debug-сборке на эмуляторе не доказывает дефект опубликованного APK
на телефоне. Настройки загрузки, исходники приложения, каталог 197 и публичные
файлы 0.3.137 этим этапом не изменены. Нового пользовательского APK нет.

## Что измерялось

Отдельный пакет `ru.dlyasvoih.app.photodiag`, версия
`0.3.137-photo-diagnostic`, собран из исходников 0.3.137. Это **debug-сборка с
наблюдателями**, не опубликованный оптимизированный APK. Прежний закрытый ключ
подписи для неё не использовался. Реальные `CardReaderScreen`,
`GuideRepository`, Room-база каталога 197 и `LocalGuideImage` сохранены.

`tools/photo_diagnostics/prepare.py` только в одноразовом checkout добавляет:
события Coil для начала/конца чтения, декодирования и результата; наблюдатель
первого CPU-вызова рисования успешного painter; метки остановки страниц.
Перед этим четыре исходных файла побайтово сверяются с исходником публичной
версии `510727a0107b8c9a3be881fb5e871d6b78a253bd`.
Кеш, ограничения размера, данные запроса, масштабирование и декодер не меняются.

Один целевой instrumentation-тест на каждой версии Android выполняет три
последовательности: открыть первую карточку, 17 свайпов вперёд и 17 назад.
Это первые 18 соседних карточек существующей книги из 194. Перед каждой
последовательностью экран удаляется из composition, кеш Coil очищается:
подтверждены 0 байт и 0 ключей. ОС-кеш файлов и JIT не сбрасываются. Интернет
отключён; отсутствие default network записано в `connectivity.txt`.

На каждую ОС приходится 105 наблюдений, 54 чтения файла (3 × 18) и 51 запрос
из кеша (3 × 17 возвратов). Совокупные 49% попаданий по всем запросам здесь
объясняются намеренной очисткой перед проходами. Для возвратов попадание — 100%.

## Результаты

у эмуляторов разные фактические размеры heap и поэтому разные штатные лимиты
кеша. Оба используют 720 × 1280, плотность 320 dpi, KVM и SwiftShader.

Во всех 108 вызовах декодирования события зарегистрированы на

В `api26/metrics.json` и `api36/metrics.json` сохранены раздельные результаты
каждой последовательности и всех запросов. `summary.json` содержит итог,

## Рисование и просмотр кадров

Просмотрены все шесть сохранённых PNG; SHA-256 и фактическое наблюдение каждого
записаны в `visual-review.json`. В четырёх кадрах `forward-end` / `returned`
фотография видна. Первый `first-open` на Android 8 показывает ещё пустую область
фото; на Android 16 — загрузку карточки. Эти два кадра **не подтверждают момент
появления первой фотографии**.

Событие `firstDraw` измеряет выполнение CPU-команды рисования painter. Оно не
измеряет передачу кадра композитору или физическому дисплею. Начальные снимки
показывают, что этой метки недостаточно для подтверждения видимого фото;
причина расхождения со снимком отдельно не изолировалась.
Время от тестовой метки ввода до `firstDraw`
включает темп Compose-теста и ввод жеста; его нельзя выдавать за задержку
свайпа пользователя. Время появления на физическом телефоне не измерено.
