## Конкретные изменения

- `tools/CHECK_PHONE.cmd` запускает русское меню физической проверки.
- `tools/check_physical_android.py` находит ADB, выбирает единственный
  физический телефон и определяет этап по установленной 0.3.133/0.3.134.
  При нескольких телефонах требуется выбор. После уже установленной 0.3.134
  откат не предлагается, прежнее сохранение данных задним числом не заявляется.
- Меню сохраняет избранное, внешний вид, галерею, навигацию и два ракурса
  каждой из четырёх моделей по действиям пользователя. Отдельный пункт
  требует подтверждённого отсутствия активной сети. Версия и SHA-256 реально
  установленного APK сверяются перед каждым снимком.
- Пункт 0 собирает ZIP только из успешных снимков текущей сессии. Архив
  остаётся на ПК, автоматической отправки нет. Функциональные проверки
  автоматически не объявляются пройденными.
- Ошибки версии, сети, устройства и хеша проверяются и при `python -O`;
  критические проверки больше не зависят от отключаемого оператора assert.
- Инструкция `research/PHYSICAL-ANDROID-0.3.134.md` дополнена простым запуском.

## Выполненная проверка инструмента

`python -m unittest discover -s tools -p test_physical_android.py -v`:
6 тестов, все прошли. Использовался **симулированный ADB**, а не телефон.
Проверены выбор/версия, архив текущей сессии без старых снимков,
отказ при активной сети, отказ для эмулятора, неоднозначный выбор двух
телефонов, отказ при чужом APK с Python -O и запрет неверного этапа.
При сборе не вызываются install/uninstall/root/clear/grant.
`py_compile`, `compileall` и `git diff --check` прошли.

Сам CMD на Windows здесь не исполнялся. Для запуска нужны Python 3 и ADB
из Android SDK Platform-Tools. Физический телефон в среде отсутствует;
прохождение проверки на нём по-прежнему не подтверждено.
