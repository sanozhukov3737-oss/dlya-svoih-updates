# Загрузка сравнения по запросу — кандидат 0.3.137

21 октября 2026 года. Правка и проверка завершены. Собран подписанный кандидат
0.3.137 / versionCode 141 с прежним каталогом 197. Этот этап не публикует APK и
не меняет штатный канал обновлений. Доступной пользователям версией остаётся
0.3.136. Исходник кандидата: `510727a0107b8c9a3be881fb5e871d6b78a253bd`.

## Изменение

Полный список вариантов для сравнения удалён из условия готовности карточки.
`GuideRepository.detail()` теперь не подписывается на `comparisonCards`.
Отдельный поток `DetailViewModel.comparisonOptions` получает подписчика только
при открытом окне. После закрытия запрос прекращается, сохранённое значение
сбрасывается; повторное открытие получает актуальный список.

Окно показывает загрузку, ошибку с повтором и отсутствие других карточек.
Порядок вариантов, ограничение двумя дополнительными карточками и загрузка
полных текстов только выбранных кандидатов сохранены. Кеш фото, подготовка
статьи, число подготовленных страниц и содержимое каталога не менялись.

## Проверки

- 30 проверок на хосте прошли; собраны debug, Android-тесты и оптимизированный
  недебажный release-APK. Задача Gradle unit tests вернула `NO-SOURCE`: отдельные
  unit-тесты не засчитываются.
- На каждом из новых эмуляторов Android 8 / API 26 и Android 16 / API 36 прошли
  **14 целевых Android-тестов**, всего 28 в завершающих проверках. Они выполнялись
  на debug-сборке того же исходника.
- `LazyComparisonTest` использует настоящие Room, репозиторий и модель карточки.
  Обратный вызов выполненных SQL подтверждает: открытие карточки, избранное и
  сохранение чтения не запускают запрос кандидатов; подписка окна запускает его;
  закрытое окно не наблюдает изменения; повторное открытие видит добавленную
  тестовую карточку. Тестовые данные существуют в отдельной базе в памяти.
- Compose-тесты проверяют состояния загрузки, ошибки/повтора и пустого списка,
  выбор двух/трёх карточек, поиск по всей категории и выравнивание таблицы.
  Проверки pager охватывают направление свайпа, дальний переход и место чтения.
  Ошибка списка в UI-тесте задаётся управляемым состоянием, а не сбоем реальной базы.
- Затем на каждом эмуляторе установлен точный публичный release-APK 0.3.136,
  выполнены свайпы и подготовлены избранное, чтение и тёмная тема. Установка
  точного подписанного кандидата через `adb install -r` сохранила все 1695 ID/
  rowid, избранное, строки чтения и настройки. На release-кандидате проверены
  офлайн-карточки, сравнение двух/трёх позиций, подтверждение при открытой
  клавиатуре и сохранение выбора после изменения системного шрифта до 1,3.
- Каталог: 197, 1695 активных карточек, 1595 изображений, integrity=ok, FK=0.
  В просмотренном crash-буфере сбоев не обнаружено. Контрольные суммы защищённых
  данных и ресурсов совпали с 0.3.136; 3D-рендер повторно не проверялся.

Первая проверка Android 8 прошла все 14 тестов, но остановилась на проверке
отключения сети: виртуальный LTE ещё оставался активным после команды. Поэтому
первый workflow в целом красный. Сценарий получил ограниченное ожидание
фактического отключения и успешно проверил **тот же APK**, без пересборки.
Между исходником APK и повторной проверкой изменились только `tools/` и workflow.
Неуспешный промежуточный результат сохранён отдельно в `attempt1-api26/`.

## Замеры перелистывания

На одном и том же эмуляторе для каждой версии Android: сначала 0.3.136, затем
обновление до 0.3.137; одинаковые тема, размер шрифта и жесты. По три серии на APK,
каждая — шесть свайпов вперёд и шесть назад по настоящим карточкам категории
из 194 позиций. Экран 720×1280, 320 dpi, KVM, программный SwiftShader.

| Среда | p95 кадра 0.3.136 по сериям, мс | p95 кадра 0.3.137 по сериям, мс |
|---|---|---|
| Android 8 / API 26 | 89 / 77 / 73 | 85 / 73 / 69 |
| Android 16 / API 36 | 81 / 65 / 65 | 73 / 65 / 65 |

В Android 8 значения в этом прогоне немного ниже; в повторных сериях Android 16
p95 одинаков. **Уверенное ускорение на телефоне не установлено.** Это короткие
последовательные прогоны с фиксированным порядком версий и меняющейся нагрузкой
runner. Метрики разных Android напрямую не сравниваются.

Удаление лишнего SQL подтверждено отдельно. `gfxinfo` измеряет кадры, а не время
готовности текста или декодирования первого фото. Попадания в кеш фото и задержки
декодирования не измерены; полевые замеры и системный установщик не проверялись.
Подробности и исходные серии — [measurements.json](measurements.json) и `api*/`.
