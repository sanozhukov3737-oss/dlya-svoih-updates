# Android 8/16 и клавиатура — приложение 0.3.136

Проверенный кандидат 0.3.136 / versionCode 140, каталог 197. Публикация запускается
отдельным workflow только после этого просмотра Android-кадров.

В Android 8 клавиатура перекрывала подтверждение в выборе карточек сравнения.
Окно теперь получает WindowInsets (`decorFitsSystemWindows=false`), учитывает
клавиатуру и системные панели. Поиск и подтверждение закреплены; пояснение,
выбранные карточки и варианты находятся в одной прокручиваемой области.
Сведения о параметре окна: [AndroidX DialogProperties](https://developer.android.com/reference/kotlin/androidx/compose/ui/window/DialogProperties).

## Фактическая проверка

- [Сборка](https://github.com/sanozhukov3737-oss/dlya-svoih-updates/actions/runs/39604907534): шаг build — success, 30 проверок на хосте, Gradle unit tests и оптимизированный недебажный APK с прежней подписью.
- [Завершающая проверка](https://github.com/sanozhukov3737-oss/dlya-svoih-updates/actions/runs/39607704093): success, Android 8 / API 26 и Android 16 / API 36, отдельные новые KVM-эмуляторы, нативный экран 720×1280 и 320 dpi.
- Сначала устанавливается точный публичный APK 0.3.135. Избранное, место чтения и тёмная тема подготавливаются через его интерфейс. Затем фактический подписанный 0.3.136 устанавливается `adb install -r`.
- До/после сверены все 1695 ID и rowid, избранное, сохранённое чтение и настройки. После установки проверены офлайн-поиск, карточка, прокрутка, поиск M14 в выборе сравнения, нажатие подтверждения при открытой клавиатуре, две/три карточки, горизонтальное смещение и шрифт 1,3. Избранное повторно открыто после остановки процесса.
- База: integrity=ok, FK=0, каталог 197, 1695 активных карточек и 1595 изображений. В наблюдавшемся прогоне нет crash/ANR.

В промежуточном прогоне сборка уже прошла, но автоматизация Android-сценария
потребовала исправлений. Завершающий workflow повторно проверяет **тот же**
неизменяемый APK из успешного шага build; пересборки в нём нет. Изменения между
исходником APK и исходником завершающей проверки затрагивают только сценарии,
workflow и запрос проверки. Публикатор проверяет это сравнение, оба успешных
Android-отчёта и контрольные суммы просмотренных кадров.

10 кадров просмотрены вручную ассистентом: `visual-review.json` фиксирует их
SHA-256 и результат. `build-result.json` сохраняет исходную пометку pending
момента сборки; её дополняет отдельный успешный визуальный протокол.
Сырые состояния, XML/PNG и результаты лежат в `api26/` и `api36/`.
Ранее неуспешные прогоны сохранены отдельно в `verification-attempts.json`,
`unpublished-attempt1.json` и `baseline-135.json`; они не выдаются за успешные проверки.

| Среда | Медиана Fully drawn, мс | 99-й перцентиль кадра, мс | PSS после избранного, МиБ |
|---|---:|---:|---:|
| Android 8 / API 26 | 946 | 250 | 32.7 |
| Android 16 / API 36 | 1238 | 97 | 42.4 |

Это исходная точка измерений, а не доказательство ускорения относительно
0.3.135. Используется программный SwiftShader; нагрузка runner и метрики
пропуска кадров различаются между версиями Android. Чистое время SQL-поиска
не измеряется: наблюдения поиска включают ADB, закрытие IME и UIAutomator.
Подробные величины — `measurements.json` и исходные `result.json`/gfxinfo.
Эмулятор не заменяет проверку производительности на физическом телефоне.
Этот прогон проверяет установку через ADB; системный установщик через приложение
и 3D-рендер здесь повторно не проверялись.

Каталог JSON, упакованная база, модельный манифест и 3D-рендерер защищены прежними
контрольными суммами из `docs/releases/app-0.3.136.json`. Тексты, изображения,
20 медицинских карточек и 19 моделей этим выпуском не изменены.
