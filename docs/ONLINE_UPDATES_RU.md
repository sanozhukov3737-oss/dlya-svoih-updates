# Интернет-обновления каталога

Начиная с v0.3.112 приложение умеет получать каталог по HTTPS. В v0.3.113 источник GitHub встроен по умолчанию: https://github.com/sanozhukov3737-oss/dlya-svoih-updates/releases/latest/download/latest.json. Вводить адрес при установке не требуется. Работа каталога остаётся доступной офлайн.

В v0.3.114 добавлены обновления самого приложения через APK. Общий latest.json может содержать поле app; инструкции по подписи, GitHub Actions и установке находятся в docs/APK_UPDATES_GITHUB_RU.md.

## Пользователь

1. Откройте «⋮ → Обновления → Проверить обновления».
2. При наличии новой версии будут показаны номер каталога, описание изменений и размер. Нажмите «Скачать и установить».
3. В «Настройках источника» можно изменить адрес и отключить проверку при запуске. Сохранённые настройки предыдущей установки не перезаписываются.

Проверка при запуске включается в настройках источника и выполняется не чаще раза в сутки. Ручная проверка доступна в любой момент, когда другое обновление не выполняется. Информация о найденном обновлении сохраняется между запусками. При закрытом приложении отдельного фонового расписания и системных уведомлений нет.

Сетевые проверки не задерживают открытие приложения и разделов. Пакет не устанавливается автоматически. Избранное и недавние сохраняются; после смены версии содержимого место чтения сбрасывается. Установка из ZIP-файла также остаётся доступна.

## Автор каталога

Используются выпуски публичного репозитория https://github.com/sanozhukov3737-oss/dlya-svoih-updates. Каждый обычный опубликованный выпуск содержит версионный ZIP-пакет и `latest.json` как прикреплённые файлы. Постоянная ссылка приложения указывает на latest.json последнего выпуска; поле url внутри JSON указывает на ZIP конкретного тега. Первый выпуск: тег catalog-147, файл catalog-147.zip. Новые выпуски публикуйте как обычные Releases, а не pre-release.

1. Подготовьте исправленный `content/catalog.json` с увеличенным `contentVersion`. Идентификаторы и `rowid` существующих карточек сохраняйте.
2. Создайте пакет существующей командой `tools/build_pack.py`. Для выпуска используйте проверенную среду сборки каталога со SQLite 3.45.1, как для встроенной базы. Изменения содержания не требуют сборки APK.
3. Разместите пакет с новым именем, например `catalog-148.zip`, и получите прямую HTTPS-ссылку.
4. Создайте описание обновления командой ниже и разместите `latest.json` последним, после готового ZIP.

Пример из папки проекта, когда пакет и адрес уже готовы:

```powershell
python .\tools\build_update_feed.py --pack .\catalog-148.zip --url "https://YOUR-HOST/catalog-148.zip" --output .\latest.json --changes-file .\changes.txt
```

Замените `YOUR-HOST` своим адресом. `changes.txt` содержит понятное пользователю описание изменений. Скрипт проверяет состав пакета, внутренние контрольные суммы, отсутствие пользовательских данных, ссылки на изображения и совпадение версии базы с манифестом. Затем вычисляет размер и SHA-256 всего ZIP; сам пакет не пересобирает.

Описание содержит `formatVersion: 1`, `contentVersion`, `url`, `bytes`, `sha256`, `changes`, `minAppCode`. Для текущего клиента минимальный код приложения по умолчанию 116 (v0.3.112). Повышайте его, только если пакет действительно требует нового приложения.

Клиент принимает HTTPS, проверяет размер и SHA-256 скачивания, затем штатную схему, содержимое и изображения пакета перед транзакционной установкой. Версия в описании должна совпасть с версией ZIP. Хеши защищают от повреждения; отдельной цифровой подписи пакета в этом протоколе нет. Адрес источника должен принадлежать автору каталога.

Чтобы обновлять интерфейс или код самого приложения, потребуется новая версия APK. Этот канал обновляет содержимое каталога.
